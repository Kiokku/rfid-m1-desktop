# RFID M1 授权加密桌面端子方案

## 1. 目标与依据

本子方案实现受控工位上的墨盒授权和储值，并建设支持这些功能的后端接口与密钥服务。授权与储值是同一个桌面端产品的两个业务模块，共用云平台登录会话、客户资料和读卡器通信能力。

本文是 [RFID M1 墨盒授权方案](./RFID_M1墨盒授权方案.md) 的实施子方案。密钥算法、卡内字段、访问控制位和 RFID 命令以总方案为唯一依据。

## 2. 交付边界

### 2.1 必须交付

- 桌面端：使用云平台账号登录、客户注册与查询、单张墨盒授权、墨盒储值，以及成功、失败或结果不确定的最小状态提示。
- 云平台集成：复用现有云平台的账号、登录和客户管理能力；由云平台管理员增加桌面端操作员账号，RFID 后端调用云平台现有接口注册客户并保存云平台客户标识。
- 读卡器接入：串口连接、`AA` 帧收发、寻卡、认证、块读写、值块初始化/加值/读值，以及断连和移卡的可见错误处理。
- 桌面端技术基线：Electron + TypeScript + React + Vite，目标环境固定为 Windows 10/11 x64；使用 Node SerialPort 直接访问 USB 虚拟串口，并由 Electron Forge 的 Squirrel.Windows maker 生成 Windows `Setup.exe`。
- 开发替身：后端客户端提供可替换的真实实现与内存模拟实现；读卡器端口只提供真实 Node SerialPort 实现。macOS 阶段不装配读卡器端口，仅用固定字节帧验证串口协议编解码；正式安装包不得启用后端模拟实现。
- 后端基础：云平台会话校验、云平台客户标识与 32 位 RFID 客户编号映射、加密密钥库、工厂根密钥保管、每卡 `Key B` 派生、全局唯一墨盒编号和审计。
- 业务接口：客户注册与查询、授权任务、储值任务，以及按 `task_id` 唯一约束实现的最简幂等完成。
- 喷码机配置操作入口：选择喷码机和客户，发起配置任务，将短时配置材料交给喷码机受保护配置接口，并回传配置结果。配置任务的后端规则和喷码机接口由喷码机 App 端子方案定义。

### 2.2 明确不做

- 不开发独立的账号、登录和客户主数据管理系统；对应能力由现有云平台提供。
- 第一版不提供客户密钥版本变更，所有客户固定使用 `key_version = 1`；卡内和喷码机仍保留该字段。
- 不提供待核验任务查询、异常任务恢复、软件隔离或解除隔离功能；结果不确定的墨盒按工位规程贴标并退出流转。
- 桌面端不生成客户密钥、工厂根密钥、每卡管理密钥或墨盒编号。
- 桌面端不持久化明文密钥，不通过界面、日志、埋点、错误上报、下载文件或会话恢复数据暴露或保存密钥。
- 桌面端不执行喷码、现场离线验卡或喷码次数扣减。
- 第一版不支持 Windows 7/8、32 位 Windows、Windows ARM 或非 Windows 平台；不使用厂商 SDK/DLL 或 Web Serial 作为读卡器主路径。
- 第一版不持久化云平台 token，每次启动均重新登录；不开发自动更新，安装和升级由人工执行。

## 3. 系统分层与责任

| 组件 | 责任 | 不得承担的责任 |
| --- | --- | --- |
| 云平台 | 管理操作员账号和客户主数据，提供既有登录、会话校验和客户注册/查询接口。 | 不保存 RFID 明文密钥或执行读写卡。 |
| Electron React renderer | 收集登录和业务操作意图，显示卡片进度及成功、失败或结果不确定状态；只通过受限 IPC 调用主进程。 | 不持有云平台 token、明文密钥、原始串口对象或通用系统能力，不自行判定后端任务已成功。 |
| Electron 主进程 | 维护短时登录会话，串联后端任务、RFID 命令、回读验收和结果提交；只向 renderer 返回非敏感业务状态。 | 不持久化 token 或明文密钥，不把敏感材料经 IPC 发送给 renderer，不改写总方案的卡布局或密钥规则。 |
| 读卡器适配层 | 只提供真实 Node SerialPort 实现，将业务操作转换为现有 RFID 协议帧，校验序号、长度、XOR 和响应状态；固定字节帧只用于编解码测试。 | 不保存任务账本；macOS 阶段不装配或打开读卡器端口，不提供应用级模拟读卡器。 |
| RFID 后端任务服务 | 维护云平台客户标识与 32 位 RFID 客户编号的一一映射，作为墨盒、授权、储值和审计的唯一事实源。 | 不重复建设云平台账号/客户主数据系统，不直接操作读卡器或墨盒。 |
| RFID 后端密钥服务 | 加密保存 `Key A` 和工厂根密钥，按任务解密或派生短时材料。 | 不在普通数据库字段、查询结果或日志中暴露明文。 |

## 4. 外部依赖与后端接口范围

接口路径仅为业务边界示例，实际路径和字段应以云平台现有接口规范为准。云平台现有登录为用户名密码接口并返回 token；Electron 主进程调用该接口并仅在当前进程内存中维护 token，React renderer 不保存 token。建议由 RFID 后端持有调用云平台客户接口所需的服务权限，桌面端不直接持有管理凭据。

| 能力 | 接口或依赖 | 必须保证 |
| --- | --- | --- |
| 操作员账号 | 云平台现有账号管理功能 | 由云平台管理员增加相应账号；本项目不开发账号管理页面。 |
| 桌面端登录 | 云平台现有用户名密码登录接口 | 返回的 token 仅由 Electron 主进程在本次运行期间持有；应用重启后必须重新登录，RFID 后端只接受有效且具备授权工位权限的 token。 |
| 客户注册 | `POST /api/rfid/customers`，后端调用云平台客户注册接口 | 云平台成功后保存 `cloud_customer_id`，分配 32 位 `customer_id` 并生成本地 `Key A`；重复请求不得重复生成映射或密钥。 |
| 客户查询 | `GET /api/rfid/customers`，数据关联云平台客户资料 | 返回云平台客户标识、名称、32 位 RFID 客户编号、注册状态和固定密钥版本 `1`，不返回密钥。 |
| 创建授权任务 | `POST /api/rfid/authorization-tasks` | 生成不可复用的 `task_id` 和 `cartridge_id`，初始状态为“进行中”；在创建响应中返回 `Key A`、`Key B` 和本次任务数据。只允许有效且具备权限的云平台会话调用，禁止缓存和记录响应体。 |
| 完成授权 | `POST /api/rfid/authorization-tasks/{taskId}/complete` | 校验 UID、块 4/6、余额和认证结果；同一 `task_id` 最多产生一条成功记录，重复提交返回原结果。 |
| 创建储值任务 | `POST /api/rfid/recharge-tasks` | 仅允许已成功授权，且该 UID 不存在未完成储值任务时创建；固定本次增加次数，并在创建响应中返回任务数据和派生 `Key B`，不返回 `Key A`。禁止缓存和记录响应体。 |
| 完成储值 | `POST /api/rfid/recharge-tasks/{taskId}/complete` | 完整核对墨盒资料、储值前后余额和任务增量；同一 `task_id` 最多产生一条储值记录，重复提交返回原结果。 |

授权与储值共使用上述四个核心接口，密钥材料随对应的任务创建响应一次返回，不再提供独立的材料接口。所有客户注册、任务创建和任务完成操作均必须审计，审计数据不得含明文密钥或完整卡块。云平台客户注册成功但本地映射或密钥记录创建失败时，使用 `cloud_customer_id` 重试本地初始化，不得再次注册客户。

桌面端在主进程中定义两个稳定接口：`BackendClient` 负责云平台和 RFID 后端调用，`ReaderPort` 负责读卡器字节流。`BackendClient` 提供真实实现和 `MockBackendClient`；`ReaderPort` 只提供真实 Node SerialPort 实现。macOS 开发构建通过 `MockBackendClient` 覆盖登录、客户查询、后端成功/拒绝/中断和结果提交不确定，读卡器相关操作保持不可用；串口编解码只使用固定字节帧测试。迁移到 Windows 后才装配真实 `ReaderPort`，并以真实读卡器验证写卡失败、移卡和串口断连。生产构建只装配真实实现，React renderer 不能选择真实或模拟实现。

## 5. 业务流程

### 5.1 客户注册与登录

1. 云平台管理员使用现有功能增加桌面端操作员账号，并赋予授权工位所需权限。
2. 每次启动桌面端后，操作员使用云平台账号登录；Electron 主进程调用云平台用户名密码接口并在内存中持有返回的 token，RFID 后端校验 token 和权限。
3. 操作员在桌面端提交客户资料；RFID 后端调用云平台接口注册客户。
4. 云平台返回 `cloud_customer_id` 后，RFID 后端分配用于卡内 4 字节字段的 32 位 `customer_id`，创建对应的 `Key A` 密文记录，固定 `key_version = 1`。
5. 后续授权、储值和喷码机配置使用 32 位 `customer_id`，并通过 `cloud_customer_id` 关联云平台客户主数据。

### 5.2 授权

1. 管理员选择客户和初始次数，桌面端创建授权任务。
2. 后端预分配全局唯一 `cartridge_id`，并在创建响应中返回本次任务材料。
3. 桌面端寻卡并读取 UID，拒绝已用于成功授权记录的 UID。
4. 以运输状态默认密钥认证，写块 4/6，初始化块 5，最后写块 7 中的密钥和权限。
5. 分别以 `Key A` 和 `Key B` 重新认证，回读块 4/6 和余额。
6. 桌面端提交验收数据；只有后端校验通过后任务才转为“授权成功”。

块 7 是不可逆切换点：写入前失败可在当前操作内重试；写入后发生中断或验收失败时，桌面端提示“结果不确定”，后端不得生成成功记录，操作员必须将墨盒贴标并退出发货流程。第一版不提供该任务的恢复或隔离接口，已分配的 `cartridge_id` 不得复用。

### 5.3 储值

1. 桌面端读取 UID，管理员输入增加次数并创建储值任务。
2. 后端确认该墨盒已成功授权且不存在未完成储值任务，向桌面端返回本任务的 `Key B` 和固定增量。
3. 桌面端以 `Key B` 认证，校验块 4/6、UID、CRC32、客户、墨盒编号和固定密钥版本 `1`。
4. 使用 `CMD_INC_CLASS` 增加块 5 余额，立即用 `CMD_READVAL_CLASS` 回读；不得直接写块 5 或修改其他块。
5. 后端仅在前后余额差恰好等于任务增量时完成任务；相同 `task_id` 的重复完成请求返回原结果，不重复记录。

加值结果不明或结果提交中断时，桌面端提示“结果不确定”，不得重新创建任务或再次加值。操作员必须将墨盒贴标并退出流转；后端保留未完成任务，并拒绝该 UID 的后续储值任务。第一版不提供桌面端查询、恢复或解除该状态的能力。

### 5.4 异常处置边界

```text
当前操作 -> 回读验收并提交成功 -> 成功，可继续流转
         -> 不可逆写入/加值后结果不确定 -> 贴标 -> 退出流转 -> 人工保管或报废
```

人工处置是第一版的工位规程，不是桌面端功能。不得通过重新授权、重新储值、修改数据库或复用 `cartridge_id` 绕过结果不确定状态。

## 6. 密钥和数据安全

- 客户 `Key A` 由 RFID 后端用密码学安全随机数生成；每卡 `Key B` 严格按总方案的 HMAC-SHA-256 规则派生。
- 第一版固定 `key_version = 1`，不提供密钥变更入口。
- 后端数据库只保存密文。解密主密钥由部署环境的受保护密钥配置或密钥管理服务提供，不存入数据库。
- 云平台 token 只保存在 Electron 主进程内存中，不写入本地文件、renderer 存储或会话恢复数据；注销、失效或应用退出时清除。
- 密钥材料只能通过 HTTPS 下发，并在 Electron 主进程中以 `Buffer` 保存；不得转为字符串、发送到 renderer 或交给界面和日志系统。
- 完成、取消、超时、注销或应用退出时，对所有明确持有密钥或包含密钥帧的 `Buffer` 执行覆零并释放引用。该措施不承诺消除运行时产生的未知副本，进程被攻破时的风险仍以受控工位边界承担。
- 创建授权和储值任务的响应包含密钥材料，必须禁止代理、网关和客户端缓存，并在日志和错误监控中脱敏请求/响应体。

## 7. 验收标准

| 验收类别 | 必须通过的场景 |
| --- | --- |
| 云平台账号 | 使用云平台新增的有效操作员账号可登录；无权限或失效会话被 RFID 后端拒绝。 |
| 客户注册 | 客户通过接口成功注册到云平台，本地生成唯一的 32 位 RFID 客户编号和版本 `1` 密钥记录，并与 `cloud_customer_id` 一一关联；重试不重复创建。 |
| 授权主路径 | 真实 F08 样卡的块 4/6、值块和扇区尾写入正确；`Key A` 和 `Key B` 均可按权限认证。 |
| 储值主路径 | 余额恰好增加任务指定次数，其他块不变，后端只有一条成功记录。 |
| 权限 | 用 `Key A` 加值、写身份块或修改扇区尾块均被拒绝。 |
| 最简幂等 | 重复提交相同完成请求时返回原结果，不重复生成授权或储值记录。 |
| 结果不确定 | 不误标成功；界面明确提示退出流转；存在未完成储值任务的 UID 不能再次创建储值任务。 |
| 会话与密钥边界 | token、`Key A` 和 `Key B` 不进入 React renderer、本地文件、日志、缓存、埋点或错误上报；重启后必须重新登录；任务结束后主进程覆零已知密钥缓冲区。 |
| 开发替身 | macOS 无真实后端时可通过 `MockBackendClient` 演示非读卡器流程及后端成功、拒绝、中断和结果提交不确定；读卡器相关操作保持不可用，固定字节帧编解码测试通过；正式安装包无法启用后端模拟实现。 |
| Windows 安装 | Electron Forge 产出的 `Setup.exe` 可在未安装开发工具的干净 Windows 10/11 x64 工位完成安装、启动、人工覆盖升级和卸载。 |
| 真实设备 | 完成连续读写、断电后重读、移卡和串口断连测试。 |

## 8. 开发顺序与交付点

1. 在 macOS 建立 Electron + TypeScript + React + Vite 工程，固化 main/preload/renderer 边界；先完成 A「引导工作台」、`MockBackendClient` 流程和固定字节帧串口编解码测试，不调用真实接口、不装配 `ReaderPort`。
2. 定义 `BackendClient` 和 `ReaderPort`，用 `MockBackendClient` 走通登录、客户和不依赖真实读卡器的后端状态，并验证生产构建不能启用后端模拟实现。
3. 将项目迁移到 Windows 10/11 x64，接入 Electron Forge Squirrel.Windows 安装配置；此后才开始真实云平台/RFID 后端、读卡器和喷码机接口工作。
4. 对接云平台用户名密码登录、会话校验和客户注册/查询接口；增加操作员账号，验证 token 只在主进程内存中存在。
5. 固化后端数据模型、固定版本密钥库和任务接口；用唯一约束验证同一 `task_id` 不重复完成。
6. 使用 Node SerialPort 实现真实读卡器适配层；以真实读卡器和样卡验证 `AA` 帧、所需 RFID 命令、访问控制位、连续操作和断连恢复。
7. 实现授权、储值和最小状态提示；验证主路径以及结果不确定时停止重复操作，并在干净 Windows 工位验证 `Setup.exe`。
8. 与喷码机 App 端联调受保护配置流程；交付只含客户编号、固定密钥版本 `1`、客户 `Key A` 和卡布局版本的短时材料，不交付工厂根密钥或 `Key B`。

本子方案完成的定义：Electron 桌面端可通过 `Setup.exe` 安装到干净 Windows 10/11 x64 工位；云平台账号可登录且 token 仅存主进程内存；客户可通过接口注册并与本地 32 位 RFID 客户编号及密钥记录关联；`MockBackendClient` 可覆盖不依赖真实读卡器的开发流程，生产构建无法启用后端模拟实现；桌面端与后端在真实读卡器和样卡上完成授权与储值主路径，重复完成不重复记账，结果不确定的墨盒能被明确停止流转，并已向喷码机 App 端提供可联调的受控配置入口。
