# RFID M1 喷码机 App 端子方案

## 1. 目标与依据

本子方案实现喷码机在出厂或受控维护阶段接收客户授权配置，并在现场无网环境中完成墨盒认证、喷码准入、成功后扣减及扣减失败锁定。

本文是 [RFID M1 墨盒授权方案](./RFID_M1墨盒授权方案.md) 的实施子方案。密钥模型、卡内布局、CRC32 覆盖范围、访问控制位和 RFID 命令以总方案为唯一依据。

## 2. 交付边界

### 2.1 必须交付

- 后端支持：通过统一密钥材料接口向有权限的桌面端返回目标客户的 `Key A`；不创建喷码机配置任务或保存配置结果。
- 桌面端交接：在受控工位上取得客户 `Key A`，组成短时配置材料并交给喷码机的受保护配置接口，在本地验证设备返回结果。
- 喷码机配置：只在组装/维护模式下写入 `customer_id`、`key_version`、客户 `Key A` 和卡布局版本，并安全持久化。
- 离线墨盒认证：寻卡、`Key A` 认证、块 4/6 读取，以及魔数、格式版本、客户、密钥版本、UID 和 CRC32 校验。
- 喷码准入和扣减：只有认证通过且余额大于 0 才允许本次喷码；只在收到喷码成功回调后减值 1 并回读确认。
- 异常锁定：认证、读值、减值或减值后确认失败时给出可见错误；扣减结果未确认时禁止下一次喷码。

### 2.2 明确不做

- 现场运行期间不依赖、查询或上传后端；所有验证和扣减均离线完成。
- 喷码机不持有工厂根密钥或每卡 `Key B`，不生成、派生或查询密钥。
- 喷码机不写块 4/6/7，不初始化或加值块 5，不创建授权或储值记录。
- 第一版不实现待扣减流水、断电恢复或补扣。喷码成功后立即断电、移卡或减值失败可能导致该次未扣减，这是已接受的范围限制。

## 3. 跨端配置契约

### 3.1 后端密钥材料接口

喷码机配置与授权、储值共用 `POST /api/rfid/key-material`。桌面端只传 `customer_id`，不传 `cartridge_id`，后端返回客户编号、固定 `key_version = 1` 和客户 `Key A`，不返回工厂根密钥或每卡 `Key B`。

接口只允许有效且具备授权工位权限的云平台会话调用，使用 HTTPS，设置 `Cache-Control: no-store`，并禁止代理、客户端、日志、埋点和错误上报记录请求/响应体。后端不保存喷码机序列号、配置动作或配置结果，喷码机也不会在现场运行时获得后端访问权。

### 3.2 喷码机受保护配置接口

现有 RFID 协议未定义安全持久化客户密钥的命令，因此喷码机方必须新增配置接口。具体传输协议可与现有喷码机通信方式一起定义，但必须满足：

- 设备物理上处于组装/维护模式时才允许调用；普通运行模式必须拒绝。
- 请求必须携带喷码机序列号、`customer_id`、`key_version`、`Key A`、扇区/块号和布局版本。
- 配置写入必须是一个整体；任一字段校验或持久化失败时，不得使用部分新配置进入运行状态。
- 配置成功后只返回不含密钥的设备序列号、密钥版本、布局版本和结果；任何查询接口均不得返回明文 `Key A`。
- `Key A` 必须保存到平台可用的受保护持久化存储中，不出现在普通配置文件、日志、崩溃报告或调试界面。

## 4. App 内部模块

| 模块 | 输入 | 输出/责任 |
| --- | --- | --- |
| 维护模式管理 | 设备物理状态、配置请求 | 判定是否允许变更客户授权配置。 |
| 授权配置存储 | 客户、密钥版本、`Key A`、布局 | 原子保存并只向墨盒认证模块提供使用能力。 |
| RFID 通信 | 寻卡、认证、读块、读值、减值请求 | 按现有协议执行命令并返回明确状态，不自行决定喷码。 |
| 墨盒认证 | UID、块 4/6、余额、已配置客户数据 | 给出“允许本次喷码”或具体拒绝原因。 |
| 喷码门禁 | 认证结果、喷码状态、扣减状态 | 确保一次只有一个未结束喷码周期，扣减未确认前不允许下一次。 |
| 余额扣减 | 喷码成功回调、本次喷码前余额 | 减值 1 并回读；确认新余额恰好为原余额减 1。 |
| 用户提示 | 认证、余额、喷码、扣减结果 | 区分墨盒认证失败、次数不足、喷码未成功和扣减失败。 |

## 5. 离线运行状态机

```text
待检测
  -> 寻卡/认证/资料校验失败 -> 拒绝喷码 -> 待重新检测
  -> 校验通过但余额 <= 0       -> 次数不足 -> 待重新检测
  -> 校验通过且余额 > 0        -> 允许本次喷码

允许本次喷码
  -> 未收到成功回调             -> 不扣减 -> 本次结束
  -> 收到成功回调               -> 减值 1 -> 回读确认
                                      -> 新余额 = 原余额 - 1 -> 本次完成
                                      -> 减值/回读/余额不符 -> 扣减失败锁定

扣减失败锁定
  -> 禁止下一次喷码
  -> 显示扣减失败，要求重新放置墨盒并完成一次全量认证
```

实现时必须防止并发喷码绕过门禁：从“允许本次喷码”到“扣减完成/本次未成功结束”之间，不得开始第二次喷码。

## 6. RFID 操作序列

1. 用 `CMD_REQUEST_TYPEA (0x1000)` 寻卡并获取 UID。
2. 使用已配置的客户 `Key A` 执行 `CMD_AUTHEN_CLASS (0x1001)`，认证模式为 `0x60`。
3. 用 `CMD_READ_CLASS (0x1002)` 读块 4/6，验证魔数 `INK1`、格式版本、`customer_id`、`key_version`、UID 和 CRC32。
4. 用 `CMD_READVAL_CLASS (0x100A)` 读块 5。余额小于或等于 0 时不得发送喷码动作。
5. 喷码成功回调到达后，用 `CMD_DEC_CLASS (0x1009)` 对块 5 减值 1。
6. 再次用 `CMD_READVAL_CLASS (0x100A)` 读值，确认新余额恰好等于本次喷码前余额减 1。

任一寻卡、认证、资料校验或读值失败都不得进入喷码。喷码成功后的减值或回读失败必须进入扣减失败锁定。

## 7. 验收标准

| 验收类别 | 必须通过的场景 |
| --- | --- |
| 受控配置 | 组装/维护模式可完整配置，普通模式拒绝；配置失败不使用部分新数据。 |
| 密钥保护 | 重启后仍可认证；查询接口、普通文件、日志、崩溃报告和调试界面都无明文 `Key A`。 |
| 正常喷码 | 本客户合法且余额大于 0 的墨盒可喷码；成功回调后余额恰好减 1。 |
| 喷码未成功 | 没有成功回调时不扣减余额。 |
| 次数不足 | 余额为 0 时禁止喷码，不发送喷码动作。 |
| 非本客户墨盒 | `Key A` 认证失败或客户编号不符时拒绝喷码。 |
| 篡改/复制 | 魔数、格式版本、UID、密钥版本或 CRC32 任一不符时拒绝喷码。 |
| 扣减失败 | 成功回调后移卡、读写失败或余额不符时显示扣减失败，并禁止下一次喷码。 |
| 并发门禁 | 首次喷码周期未结束时，第二次喷码请求被拒绝。 |
| 断电重启 | 配置和卡上余额保持；重启后必须重新进行全量墨盒认证才允许喷码。 |

## 8. 开发顺序与交付点

1. 先以真实 F08 样卡验证喷码机 RFID 读写能力、访问控制位和值块减值；固化认证模块的输入/输出。
2. 实现受保护配置接口和密钥持久化；通过模式限制、原子更新、重启和明文泄漏检查。
3. 实现墨盒认证、喷码门禁、成功回调后扣减和异常锁定；使用真实喷码成功/失败事件验证状态机。
4. 联调统一密钥材料接口和桌面端操作入口；通过“后端返回 Key A—桌面端组成并传递配置—喷码机保存—桌面端本地验收—无网运行”的端到端验收。

本子方案完成的定义：喷码机可在受控模式安全接收配置，断网和重启后仍能只允许本客户合法墨盒喷码，并对每次喷码成功回调执行且仅执行一次可确认的减值。
