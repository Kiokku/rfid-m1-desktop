# Windows 开发环境迁移检查清单

本清单是从 macOS 的固定 `AA` 字节帧编解码迁移到 Windows 10/11 x64 真实读卡器开发前的交接门槛。完成本清单前，不接入云平台、RFID 后端、喷码机或真实串口。

## 1. 受控工位与构建工具

- [ ] 使用干净的 Windows 10/11 x64 工位；不支持 Windows 7/8、32 位或 ARM。
- [ ] 安装与项目锁定版本兼容的 Node.js LTS、npm 和 Git；在仓库根目录执行 `npm ci`。
- [ ] 安装 Visual Studio Build Tools 的 Desktop development with C++ 工作负载，以便后续 Node SerialPort 原生模块按 Electron 版本重建。
- [ ] 执行 `npm test`、`npm run typecheck` 和 `npm run build`；三个命令均通过后才增加 Windows 专属依赖。
- [ ] 记录 Node、npm、Windows 版本和 Electron 版本，作为首次设备问题的可复现环境信息；记录中不得包含 token、客户密钥或完整卡块。

## 2. 读卡器和串口驱动

- [ ] 使用厂商提供的 USB 虚拟串口驱动，连接读卡器后在设备管理器确认其 COM 端口与硬件标识。
- [ ] 使用已知正常的 USB 数据线和直连端口；记录 COM 端口、驱动版本和读卡器固件版本。
- [ ] 依据实际设备资料确认波特率、数据位、校验、停止位和超时；这些值尚未在 macOS 编解码阶段固定。
- [ ] 首次接入前，确认读卡器使用厂商 `AA` 协议，而非 SDK/DLL 或 Web Serial 路径。

## 3. 废弃样卡和安全边界

- [ ] 准备可反复写入、已明确标记为“开发/废弃”的 F08 卡贴样本；不得使用待出货墨盒或生产卡贴。
- [ ] 样卡操作使用开发后端数据时，其结果不得进入生产后端记录或发货流转。
- [ ] 真实 `ReaderPort` 只在 Electron 主进程装配；renderer、preload 和日志不得取得串口对象、token、客户密钥、每卡管理密钥或完整卡块。
- [ ] 所有已知密钥和命令缓冲区在操作结束、取消、超时、退出或失败后覆零；这只减少已知副本，不宣称 JavaScript 运行时绝对擦除。

## 4. 首次启动验证

- [ ] 先启动应用并确认每次启动都要求登录；未登录时读卡器相关业务不可用。
- [ ] 装配真实 Node SerialPort `ReaderPort` 后，确认能枚举并打开记录的 COM 端口，且拔出设备会报告断连而不是成功或等待。
- [ ] 使用固定 `AA` 编解码测试的命令顺序验证真实设备：TypeA 寻卡、扇区认证、块读/写、值块初始化、加值、读值。
- [ ] 使用废弃 F08 样卡验证移卡、重新插卡和读卡器重连；失败响应应保留类型化原因，不显示密钥或完整卡块。
- [ ] 在独立干净 Windows 工位验证 Electron Forge 的 Squirrel.Windows `Setup.exe`：安装、启动、人工覆盖升级和卸载均不依赖开发工具。

## 5. 移交记录

- [ ] 将构建工具、驱动、读卡器、COM 参数和启动验证结果写入受控部署记录。
- [ ] 任何真实云平台、RFID 后端或读卡器失败的原始诊断，先做 token、密钥与完整卡块脱敏后再保存或共享。
